# Evidence-Based Policymaking — LumaChart Alignment

Framework: **Pew-MacArthur Results First Initiative, *Evidence-Based Policymaking: A Guide for
Effective Government* (Nov 2014).** Five components. LumaChart is built to operationalize all five —
because its thesis (*evidence on the record*) is the same lever Pew names: turning the
**administrative/operational/compliance data an EHR already collects into evidence.**

> "Make better use of administrative data — information typically collected for operational and
> compliance purposes — to enhance program evaluations." — Results First, Component 5

## The five components → LumaChart

| # | Pew component | What it asks | LumaChart feature that delivers it |
|---|---|---|---|
| 1 | **Program assessment** | Inventory programs; categorize by evidence of effectiveness; identify ROI | Embedded **evidence engine** + **annotated bibliography**; every feature carries a **PMID / §170.315 / authority** chip (categorized by its evidence); "Plans & value" + denial-prevention (ROI) |
| 2 | **Budget development** | Put evidence into budget/policy in user-friendly formats; performance requirements in grants/contracts | **Revenue & analytics** and **burden-lab** metrics in plain dashboards; non-dilutive **NIH SBIR** (evidence-based funding); readiness & contracts view |
| 3 | **Implementation oversight** | Quality standards; fidelity monitoring; data-driven reviews | **AI governance registry + PCCP** (fidelity/quality standards for models); **SAFER** guides + audit logs; CWO **action plan** with data-driven reviews |
| 4 | **Outcome monitoring** | Meaningful measures; audit data systems; report regularly | **Burden lab** (audit-log time + validated burnout instrument); pinned metrics (face-time ratio, after-hours EHR); **EHR8/WOW8**; **equity** (disaggregated) dashboards; **data-extract report** |
| 5 | **Targeted evaluation** | Rigorously evaluate new/untested programs; use administrative data; centralized repository | **RSI discovery loop** (hypothesis → rank → test → learn); **research console** (consented, IRB-gated) + de-identified **registry** as the centralized repository — evaluation built on the record's administrative data |

## The one-liner
**LumaChart is evidence-based-policymaking infrastructure for health:** it turns the operational and
compliance data a certified EHR already collects into program assessment, outcome monitoring, and
targeted evaluation — the exact capabilities Pew says governments lack.

## Where this gets used
1. **CMS MES IT Standards RFI** (see [[cms-mes-it-standards-rfi]] / `docs/` RFI work): structure the
   response on these five components — CMS/Medicaid speaks this language. LumaChart is the
   provider-facing node that makes Medicaid data *evidence-ready* (interoperable, cited, evaluable).
2. **Investor + technical narrative:** the public-sector market thesis — governments are increasingly
   *required* (federal funding incentives; 100+ state laws) to fund evidence-based programs; LumaChart
   supplies the evidence layer.
3. **Product guardrail:** every new feature should answer "which of the five components does this
   serve, and what's its citation?" — the same discipline as citing PMIDs.
